What a ward engineer needs, and what we built

Detecting a pothole is solved. Knowing how big, where exactly, and whether it was really repaired is not.

  • Measure: dashcam frame → calibrated top-down view at 1 cm/pixel → damaged area in m² ± uncertainty
  • Locate: on a named road, by chainage, also in the 3.1 km tunnel
  • Track: the same defect across passes → new / unchanged / degraded / repaired
  • Act: an Amazon Nova agent groups defects into work packages, estimates hot-mix, ranks by nearby schools and hospitals, and requests human approval

28.6 km real Mumbai loop: Marine Drive, Coastal Road, Worli Seaface, Haji Ali (OpenStreetMap geometry, 84 schools / hospitals / bus stops).

OpenCV 5 geometry: from pixels to square metres

ChArUco calibration (RMS 0.164 px) → per-frame road pitch from lane lines → bird's-eye view at 1 cm/px → area is a pixel count.

2.1% area error with perfect outlines (target ≤ 5%): the geometry is not the bottleneck. Frame triage keeps 284 frames/km and loses no defects; faces and plates are blurred before storage; median position error 2.6 m (raw GNSS 6.2 m).

The human gate: the agent can only ask

A Step Functions workflow holds the approval token in the database; the agent never sees it.

Agent drafts work order→request_human_approval→Step Functions waits (task token, 7 days)→Engineer: approve / reject→filed: MOCK ticket · or · rejected: override recorded
  • Road-wide request “Plan repairs for Khan Abdul Gaffar Khan Marg” → 24 work packages in 78 s (84 k Nova Pro tokens ≈ $0.10)
  • Approved (priority 1, 3.40 m²) → state filed, ticket MOCK-aea1bb9b…: nothing is sent to a real authority
  • Rejected (0.02 m², “re-inspect first”) → state rejected, recorded as an override
  • No answer → the request expires after 7 days

Honest note: the agent's final text summary listed one package twice. The packages, numbers and approvals in the database were correct, because code computes them, not the model's prose.
